# Architecture

## Prototype
- Multi-page HTML. Each screen is a thin shell generated by `tools/build.py`, with `data-page` naming a handler registered through `N.page()`.
- `core.js` provides:
  - the store `N.db`: localStorage, audited saves
  - `N.table`: search, filters, sort, pagination, bulk actions, export
  - `N.form`: validation, conditional and calculated fields, file and image preview, values retained on failure
  - `N.modal` / `N.confirm`, `N.chart` (Chart.js), `N.calendar`, `N.tabs`, `N.timeline`
- `components.js`: `N.resource` gives every module the same list/create/edit/view/workflow behaviour.
- `layout.js`: one shell, with navigation per portal (`app`, `vessel`, `seafarer`, `platform`).

## Production target (PRD 2.3)
A modular monolith:
- `Nyovara.Domain`: entities, value objects, rest-hours rule engine
- `Nyovara.Application`: use cases, validation, permissions
- `Nyovara.Infrastructure`: EF Core, SQL Server, storage, email/SMS adapters
- `Nyovara.Web`: MVC views from these pages plus `/api/v1`
- `Nyovara.Worker`: expiry alerts, sync processing, backups

Hosting: Windows Server / IIS over HTTPS.

## Moving logic to C#
Several pieces of frontend logic must become C# services, with server-side authorisation on every request:
- the rest-hours engine (`resthours.js` → `RestHourComplianceService`)
- the deployment checks (`N.deployIssues`)
- crew status transitions (`N.CREW_TRANSITIONS`)
- the payroll calculation
- allotment validation
